# wxbot 全量进化路线图设计（R1~R5）

日期：2026-10-23
状态：已与用户逐节确认
基线版本：v1.4.13（230 个测试）

## 1. 背景与目标

wxbot 已具备：私聊拟人回复+长期记忆、群答疑 RAG（图片/语音/引用多模态）、免@智能接话、群友画像、全量冷启动、违禁词监控、群定时任务、Web 控制台+一键升级+国内镜像。

用户要求三大方向**全量推进、不打折扣**：

1. **群内提效与管理**：未解问题闭环追踪、群精华自动沉淀、群秩序自动化、多群运营驾驶舱
2. **个人智能助手**：群精华日报+错过消息补报、约定/日程提醒、跨聊天记录问答、主动关怀代聊
3. **易用性**：微信里一句话操控（给自己）、零配置安装（给亲友）、集中部署管理（给团队）、稳定自愈少操心

**产品形态共识**：wxbot 是 PC 应用，守着微信"像人坐在微信前操作"。助手的一切输入输出都在微信内完成；Web 控制台只做管理不做交互入口。

## 2. 路线：场景闭环纵切（方案 A，已采纳）

每个里程碑交付 1~2 个端到端可感知的闭环，三条线轮转；高危主动功能（代聊）后置于记忆与提醒跑稳之后。

| 里程碑 | 版本 | 内容 | 复用基建 |
|---|---|---|---|
| R1 感知闭环 | v1.5.0 | 群日报 + 错过补报 + 驾驶舱雏形 | group_tasks 调度、mining 摘要、store 统计 |
| R2 记忆闭环 | v1.5.x | 跨聊天问答 + 群精华主题库 | 画像/挖掘、KB 网关、冷启动管线 |
| R3 主动闭环 | v1.6 | 约定提醒 + 关怀代聊 + 未解问题闭环 + 群秩序自动化 | pending_issues、contact_memories、人设引擎 |
| R4 易用/分发 | v1.7 | 一句话操控 + 零配置通道 + 自愈守护 | 管理员命令、updater、镜像 |
| R5 团队化 | v1.8+ | 集中部署/远程升级/多号管理 | 227 镜像、备份迁移 |

## 3. 总体架构

### 新增模块（单一职责、独立可测）

| 模块 | 职责 | 里程碑 |
|---|---|---|
| `wxbot/scheduler.py` | 通用定时调度器：把 group_tasks 的 today 槽点判定泛化为多任务类型注册（日报/补报/关怀/催办/统计聚合） | R1~R3 |
| `wxbot/digest.py` | 群日报生成 + 错过消息补报（不在场时谁@我/私信我/热点） | R1 |
| `wxbot/recall.py` | 跨聊天记录检索问答（本地检索 + LLM 整合出处回答） | R2 |
| `wxbot/reminders.py` | 约定/日程自动识别与到期提醒、销项 | R3 |
| `wxbot/care.py` | 主动关怀代聊（记忆+热度生成问候，强护栏） | R3 |
| `wxbot/followup.py` | 未解问题闭环（认领→催办→归档入库） | R3 |
| `wxbot/command.py` | 微信一句话操控（自然语言意图路由，泛化 #命令体系） | R4 |
| `wxbot/watchdog.py` | 自愈守护（微信进程/窗口/登录态监测恢复、守护拉起） | R4 |
| `wxbot/gate.py` | 动作闸门 ActionGate：全主动动作的频控/时段窗/急停/审计统一出口 | R1~R3 |

### 复用不动

消息管线（DB poll→群/私聊分发）、人设引擎（personas）、画像（profiles）、KB 网关、mining 摘要、store、Web 控制台、updater/镜像升级。所有新功能的输出动作走既有安全出口（dry_run、30 秒去重、字数上限、引用按正文定位）。

### store 新表

- `digest_log`：每群日报水位（锚定日期 + 消息 sort_seq），防重推
- `reminders`：约定（谁/何事/何时/状态/来源消息锚点）
- `daily_stats`：每日每群聚合（消息量/活跃人数/热点词/未解数），驾驶舱数据源
- `care_log`：关怀动作记录（频控与审计依据）
- `missed_cache`：错过消息缓存（@未答/非白名单私聊/紧急分级）

### 关键设计决策

1. **「文件传输助手」= 主人对话台**（R2 落地，R4 复用）：主人发给文件传输助手的消息（`is_self=True`，当前被忽略）识别为"对助手说话"，成为跨记录问答与一句话操控的统一入口——手机上随时可用的零成本助手会话。
2. **日报默认推送文件传输助手**（可配任意会话）。
3. **非白名单私聊进补报摘要**（用户确认无隐私顾虑，保留内容摘要而非仅元数据）。

## 4. R1 详设（v1.5.0）

### 4.1 群精华日报

- 配置：`app.daily_digest: {enabled: true, hour: 21}` + 群级 `digest.enabled` 开关；Web 驾驶舱页可视化配置
- 内容（每群一节，多群合成一份）：
  1. 今日热点话题与争论点（复用 mining 摘要）
  2. 未解问题清单（读 pending_issues，为 R3 闭环打底）
  3. @我未回 / 找我的事（见 4.2）
  4. 值得看的发言（画像+LLM 挑 1~3 条）
- 水位：digest_log 锚定日期+sort_seq，重启只补不重
- 发送：总日报超长自动分条（按群边界切分）发送，不截断内容

### 4.2 错过消息补报

- 收集：启用群 @我未答 → missed_cache；非白名单联系人私聊 → 汇总（谁/几条/什么事）；紧急特征（急/尽快等，LLM 三级分级）→ 急件**立即**推文件传输助手，不等日报
- 即时指令：管理员 `#补报`（R4 自然语言化）

### 4.3 多群驾驶舱雏形（Web 只读）

- 新卡片「驾驶舱」：每启用群一行——今日消息量/活跃人数/热点词/未解问题/待沉淀/最后活动；数据 = store 既有统计 + daily_stats 聚合（日报跑完顺带写）

### 4.4 R1 验收

- 配置一次后每天 21 点自动收到多群总日报（文件传输助手）
- 不在场时急件即时推送；日常漏看进日报"找你的事"
- Web 驾驶舱一屏看全群态势

## 5. R2 概要（v1.5.x）

- **跨聊天问答（recall）**：文件传输助手对话台；检索面=全部启用群+私聊历史（时间/人/关键词 + FTS5 索引）；答案必须带出处（谁/哪群/大概时间）；LLM 整合而非罗列
- **群精华主题库**：挖掘 QA 自动按问题聚类成主题（非流水账）；重复提问先撞主题库命中；KB 写权限开通后同步团队库

## 6. R3 概要（v1.6）

- **reminders**：LLM 抽取约定（谁/何事/何时，基准日处理"明天/下周五"）；到期：你的事推文件传输助手、群里的事 @相关人；回复"已完成"销项
- **care**：contact_memories + 关系热度（多久没聊）生成问候；护栏：每人每周≤1、仅 8:00~22:00、先 dry_run 演练、Web 审批队列可选、一句话急停
- **followup**：pending_issues 升级——识别 → 群里问"谁在跟？" → 定期催办（可配）→ 解决归档自动生成 QA 入库
- **群秩序自动化**：发言频次异常提醒、退群预警、新人进群自动引导常见问题（指路主题库）；定时开闭群仅在机器人号为群主的群生效（微信权限如此），非群主群只做提醒

## 7. R4 概要（v1.7）

- **command**：文件传输助手 + 群内管理员@双入口；自然语言意图（暂停群/补报/建提醒/查记录/开关功能）；意图路由 LLM + 白名单动作映射，未识别明确说不支持
- **零配置（亲友）**：内置默认模型通道（用户网关发额度），首启只剩"装→扫码→用"
- **watchdog**：微信进程守护拉起、掉线检测告警、wxbot 开机自启+崩溃重启；只做恢复不做风控规避

## 8. R5 概要（v1.8+，视需求）

- 亲友一键包：预配网关导出"安装+配置"合体包；远程强制升级/灰度
- 多号集中管理：227 轻量心跳上报 API（版本/状态一页看全）

## 9. 动作闸门（ActionGate，全路线安全底座）

所有主动动作统一过闸：

- 频控：全局每小时上限 + 每会话每日上限；关怀类独立限频
- 时段窗：默认 8:00~22:00，急件补报豁免
- 急停：`#急停 主动` 立停全部主动功能，Web 开关同步
- 审计：动作落 log 表，Web「动作审计」卡片（触发源/目的地/摘要）
- 幂等：水位/消息 seq 锚定，重启不重发
- 降级：LLM 失败重试 1 次降机械摘要；UIA 失败走既有重试→前缀降级；scheduler 任务异常互相隔离
- 默认姿态：新主动功能上线默认 dry_run，Web 看演练日志后再开真发

## 10. 测试策略

- 自包含 fake 套件（FakeDB/FakeDriver/FakeLLM），每模块独立：
  - scheduler：时间槽判定、错过补跑、水位幂等
  - digest：结构断言、水位、紧急分级
  - recall：检索排序、出处引用、过滤
  - reminders：时间解析（基准日/跨月）、到期触发、销项
  - care：护栏全断言（频控/时段/演练/急停）
  - command：意图路由每意图≥2 正反例
- bot 挂载全部新消费器后的消息流转冒烟
- 目标：套件 230 → 300+

## 11. 实施顺序

R1（本路线图第一个子项目）→ 走独立 spec→plan→implementation 循环；R2~R5 各自开工前再细化，架构按本设计预留接缝。
